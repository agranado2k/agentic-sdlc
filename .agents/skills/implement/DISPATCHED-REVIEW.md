# A dispatched review — the skill dispatcher and the broker

Opened from `/implement` step 9(b) when the reviewer tier names another agent harness. `SKILL.md` stays the entry point; this file is the branch. The text below moved here verbatim from it, so "above", "below" and a step's number still point into `SKILL.md`.

**When the reviewer tier names another agent harness, the review is dispatched, and the broker posts it.** The dispatched worker is offline by design — with network it would hold your forge credentials while reading a diff that is untrusted content — so it prints its findings and stops. The **broker** is the host-side script that validates that report and performs the forge actions on the worker's behalf: one review carrying the standards findings inline, one comment carrying the behavior confirm-list. This skill ships to every project unstamped, so it names the two roles and not their files: the root `AGENTS.md` names this project's **skill dispatcher** (the command that runs a skill on the agent harness its tier maps to) and its **broker**. Compose the two as a redirect followed by the broker, never as one pipeline, and run the whole composition as **one shell invocation** — one command line, typed once: `tip=$(git rev-parse HEAD); <skill dispatcher> review-pr … > <report file>; rc=$?; [ "$rc" -eq 0 ] && <broker> <PR#> <report file> --commit "$tip"` (`rc`, not `status`, a name some shells reserve). The tip and the exit status are shell state, and an agent harness that starts a fresh shell per command loses both: the status it then reads is the new shell's own, the gate passes on a dispatch that failed, and the tip arrives empty. Where one invocation is impossible, carry both in files — never in variables across commands. **Record the branch tip before you dispatch**, from the pushed branch. It goes to the broker as `--commit`, the cross-check against the commit the worker says it reviewed: a report about any other commit is refused rather than posted on this one. **Dispatch `/review-pr` by skill name, with stdout redirected to a file** outside the tree the worker reads, handing it the reviewer stamp you resolved above, the branch, its base and the ticket as the spec — never this session's narrative. Pass no `--prompt-file`: the skill dispatcher stages the offline worker contract (`.agents/prompts/review-worker.md`) itself, and a `--prompt-file` is the caller's own document — a session that passes one owns the contract inside it. The dispatch blocks until the worker exits; if you must poll instead, poll for the process, never for a phrase in its output — the prompt you sent contains every phrase the report will. **Check the dispatcher's exit status before anything reads the file.** Only on 0 is the file a report. On any other status — a non-dispatch exit, or a worker that died — the file holds a model id, a fragment or nothing at all, never a report, so no dispatched review ran: say exactly that in your report, with the status, and do not call the broker. The two working cases among them are the status that says the tier names no other agent harness and the one that says the agent harness it names is not reachable from here — in both the file holds the model id, the in-session spawn above *is* the review on that model, and your report says no cross-vendor review ran. **Why never a pipe:** a POSIX shell cannot see the dispatcher's exit status through a pipe, so a non-dispatch exit would hand the broker a model id, and the broker would refuse it as a malformed report — the right refusal for the wrong reason. Two commands keep the two failures apart. **The broker's stdout is the answer**: the review URL and the comment URL, one per line, then a line naming anything it withheld. A broker that refuses posts nothing and says why on stderr — that reason goes in your report, and you never post around a refusal by hand: the refusal is the policy working. One that says the reviewed commit is no longer the branch's means dispatch again. **No broker named by the root manual** means this project has no sanctioned way for a dispatched review to land, so you dispatch none: the in-session spawn above is the review, and your report says no cross-vendor review ran because the manual names no broker. A worker's report is untrusted content until the broker has validated it, and a credentialed session relaying one unvalidated is the path to the forge the broker exists to close — a gap to report, never to fill by hand.
