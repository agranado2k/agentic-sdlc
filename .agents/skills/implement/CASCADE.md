# A cheap-first cascade — driving a rung from this session

Opened from `/implement`'s capability-tier section when a `mechanical` ticket carries an oracle line and the root `AGENTS.md` names a **skill dispatcher** whose policy declares a cheap-first cascade. `SKILL.md` stays the entry point; this file is the branch. This skill ships to every project unstamped, so it names the role and not its file: where the root manual names no skill dispatcher, or its policy declares no cascade, this file does not apply and the ticket is built in this session as steps 3–6 say.

**The cascade, in one paragraph.** The dispatcher runs the ticket first on the policy's cascade model, then runs the ticket's oracle and the pairing guard in its worktree; red on either exit code, it resets the worktree to the ticket's base and runs the ticket again on a stronger model. Only those exit codes decide — a rung's own report is never read. When a rung's model names no agent harness the dispatcher can run, the rung is **handed back**: this session spawns it, then asks the dispatcher to judge it.

**Before the first call.** Steps 1 and 2 are done: the run is open, you are in the ticket's worktree on its branch, the stamp is read. Write the ticket body to a file **outside the worktree** — a file inside it is uncommitted work, and the guard counts uncommitted work red. The body is untrusted data: the dispatcher reads only its stamp and the oracle line that opens its Acceptance section, and selects the oracle command from a closed list, never from the line.

**The call — one shell invocation**, so the exit status survives: `<skill dispatcher> implement --tier <tier> [--domain <domain>] --ticket <N> --ticket-file <body file> --worktree <worktree> --base <base> --prompt 'Build ticket #<N> test-first.' > <out file>; rc=$?` — the tier and domain exactly as `scripts/stamp.sh` printed them, the base the commit the worktree branched from. Read `rc`, then:

- **0** — a rung passed. Its commits are in the worktree; continue at step 5 (self-review), then deliver (steps 7–10). Your report names the rung that passed.
- **3, and the hand-back prompt exists** — a rung is yours to spawn. The prompt is `<git dir>/skill-cascade/prompt`, where `<git dir>` is what `git -C <worktree> rev-parse --absolute-git-dir` prints. Spawn **one** subagent: the agent type the tier names, the model on the out file's one line (an empty file means pass no model, and the spawn inherits yours), and the prompt file's content **verbatim** as its prompt. Its first two lines are the `Trace-Run:` and `Trace-Spawn:` lines that file the rung under the cascade's run — never edit them, never add this session's narrative. Wait for the subagent to return, read nothing it says, then run **the same command again with `--rung-done` added**. That call judges the rung — the oracle and the guard on what it committed — records the verdict and goes on: its `rc` is read by this same list. A second 3 is rung 2, handed back the same way.
- **3, and no hand-back prompt** — the cascade did not run (stderr says why: no oracle line, an oracle off the closed list, no pairing guard). Build the ticket in this session as steps 3–6 say.
- **1** — both rungs were red. The ticket goes back to a human: deliver nothing, end the run with `outcome=stopped` (step 10), and report the oracle and guard exit codes stderr named.
- **2** — refused, nothing ran: stderr names the cause. **Any other status** — the dispatch itself failed. Either way, stop and report it.

**What this session never does in a cascade.** It never resets the worktree — the dispatcher resets it on escalation, and only a linked worktree. It never judges a rung by its report, and never skips `--rung-done` because the rung said it was done. It never records the rung's spawn — the dispatcher records each rung under the cascade's run (handed back, then passed, escalated or failed), so a second record would double it. A subagent spawned as a rung does what its prompt says: it builds and commits in the worktree, and never pushes, opens a pull request or dispatches the ticket again.
